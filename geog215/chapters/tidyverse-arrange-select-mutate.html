6  Into the Tidyverse: arrange, distinct, select, and mutate

NoteLearning objectives

By the end of this chapter you should be able to:

  1. Sort the rows of a data frame with arrange(), in either direction and by more than one column.
  2. Find the unique values, or unique combinations of values, in a data frame with distinct().
  3. Keep only the columns you need with select().
  4. Make new columns from existing ones with mutate().
  5. Chain these verbs and filter() together with the pipe to answer a question step by step.

In the last chapter you met the tidyverse, looked inside the flights data with glimpse(), and kept the rows you needed with filter(). This chapter adds four more dplyr verbs. Two of them work on rows: distinct() finds the unique values in a column, and arrange() sorts the rows. The other two work on columns: select() keeps the columns you name, and mutate() makes new ones. With filter(), these five verbs cover most of the day-to-day work of getting data into shape.

The examples keep using the nycflights13 data, so you can build each answer one step at a time. By the end of the chapter you will be able to answer questions such as “where can I fly from JFK in under three hours?” and “what was the fastest flight out of New York in 2013?”

TipWarm-up: why doesn’t this code work? 
flights |> filter(month = 1)

Run it in the box below and read the error before you look at the answer.

R says it “detected a named input” and asks “Did you mean month == 1?” A single = names an argument; a comparison needs a double ==. The fix is flights |> filter(month == 1). dplyr’s error messages often tell you exactly what went wrong, so read them before you change anything.

6.1 Verbs for rows and verbs for columns

6.1.1 Two kinds of verb

Every dplyr verb takes a data frame as its first argument and returns a new data frame, which is why they chain together so well with the pipe. But they change different things. Some verbs change which rows you have, or the order they are in. Others change which columns you have (Table 6.1).

Keeping the two groups in mind helps you plan a pipe chain. If the question is about which flights, you need a row verb. If it is about which information about each flight, you need a column verb.

6.1.2 Where this fits

These verbs all belong to the Transform step of the data science workflow you met in the last chapter. None of them changes what a row means: before and after, each row of flights is one flight. They only change which flights you keep, the order they are in, and which facts about each flight you can see. That relies on the data being tidy: each variable is a column, each observation is a row, and each value has its own cell.

Give distinct() more than one column and it keeps each unique combination of their values. Which airports are linked by a direct flight from New York?

There are 224 origin and destination pairs. That is more than 105, because many destinations are served from more than one New York airport: Atlanta, for example, appears three times, once with each origin.

To count unique values, pipe the result into nrow(), as in flights |> distinct(dest) |> nrow(), which returns 105. If you want to keep the other columns, distinct() has an argument for that, .keep_all = TRUE, which keeps the first row it finds for each unique value.

6.3 Sorting rows with arrange()

6.3.1 Sorting by one column

arrange() sorts the rows of a data frame by the column you name. Add it to the end of the JFK question to list the destinations alphabetically:

The same 50 rows now start with ACK (Nantucket), ATL (Atlanta), and AUS (Austin). arrange() changes the order of the rows, never how many there are. It sorts in ascending order by default: A to Z for text, smallest to largest for numbers.

6.3.3 Largest first

To sort in descending order, largest first or Z to A, wrap the column in desc(). Which flights left latest?

The longest departure delay in 2013 was 1,301 minutes, nearly 22 hours, on a flight from JFK to Honolulu on January 9. (The select() at the end keeps a few columns so the result fits on the screen. It is the subject of the next section.)

For a numeric column, a minus sign does the same job: arrange(-dep_delay) sorts from largest to smallest. The minus sign only works on numbers, though, while desc() also works on text, so desc() is the safer habit.

Missing values always go to the end, whichever direction you sort. The flights with no dep_delay (the cancelled flights) are at the bottom of both arrange(dep_delay) and arrange(desc(dep_delay)).

6.3.4 Sorting by two columns

What does this code do? Read it one step at a time, and predict the order of the Atlanta (ATL) rows before you run it.

distinct(origin, dest) keeps the 224 unique pairs. arrange(dest, origin) sorts them by destination first. When two rows have the same destination, which is called a tie, it uses the second column, origin, to decide their order. All three New York airports fly to Atlanta, so ATL appears three times, and those three rows are sorted by origin: EWR, JFK, LGA. You can name as many columns as you like; each one breaks the ties left by the one before.

6.5 Making new columns with mutate()

6.5.1 Average speed

mutate() adds new columns to a data frame, calculated from the columns it already has. Its arguments take the form new_name = calculation. How fast was each flight? distance is in miles and air_time is in minutes, so distance divided by air time is miles per minute, and multiplying by 60 gives miles per hour:

mutate() did the calculation for every one of the 336,776 flights at once. That is because arithmetic in R is vectorized: dividing one column by another divides each value by the value in the same row, without a loop. The new column goes at the end of the data frame. Here, select() keeps it and the columns it was made from, so you can check the arithmetic: the first flight flew 1,400 miles in 227 minutes, or about 370 miles per hour.

The 9,430 flights with no air_time (most of them cancelled) get an avg_speed of NA, because any arithmetic with a missing value gives a missing value.

ImportantThink about it

The fastest flight averaged 703 miles per hour: a Delta flight from LaGuardia to Atlanta on May 25, which flew 762 miles in 65 minutes. A passenger jet usually cruises at about 550 to 580 miles per hour. The typical LaGuardia to Atlanta flight in 2013 took 112 minutes, at about 408 miles per hour.

Do you believe it? A strong tailwind can push a plane’s speed over the ground well above its cruising speed, but a 65-minute flight to Atlanta is still extraordinary. It could also be an error in the recorded air time. Either way, a value that is far from all the others, an outlier, deserves a second look before you report it. Sorting with arrange() is one of the quickest ways to find them.

6.6 Practice: the longest flight

Put it all together. These steps follow the in-class exercise.

Step 1: set up. Start a new R Markdown file, and load the packages in the first chunk:

library(tidyverse)
library(nycflights13)

Then take a quick look at the data with glimpse(flights).

Step 2: the longest flight. What is the longest domestic flight from New York? Sort by distance, largest first, and keep the columns that answer the question. Try it before you look at the answer:

flights |>
  arrange(desc(distance)) |>
  select(origin, dest, distance, air_time)

The longest flight is from JFK to Honolulu (HNL), 4,983 miles. Every one of the top rows is that same route, because it was flown every day. Add distinct(origin, dest, distance) after the arrange() to see the longest routes rather than the longest flights: the second is Newark to Honolulu, 4,963 miles.

Step 3: how fast was it? Add a mutate() that calculates avg_speed, and include it in the select().

flights |>
  arrange(desc(distance)) |>
  mutate(avg_speed = distance / air_time * 60) |>
  select(origin, dest, distance, air_time, avg_speed)

The first flight in the list took 659 minutes, an average of about 454 miles per hour. But the next took 638 minutes and the one after 616, so the speeds differ. Over the year, JFK to Honolulu flights averaged between about 433 and 516 miles per hour. The distance is the same every day, so the difference is all in air_time. Why might the same route take an hour longer on one day than another? Think about the wind over the Pacific, and the route each flight was cleared to fly.

6.8 Summary

  • dplyr verbs work either on rows (filter(), distinct(), arrange()) or on columns (select(), mutate()). Each takes a data frame first and returns a data frame, so they chain with the pipe.
  • distinct() keeps one row for each unique value of the columns you name, or each unique combination if you name several. It keeps only those columns.
  • arrange() sorts rows, in ascending order by default. Wrap a column in desc() for descending order. With several columns, each one breaks the ties left by the one before. Sorting never adds or removes rows, and missing values go last.
  • select() keeps the columns you name, in that order. - drops a column, : keeps a range, and starts_with(), ends_with(), and contains() pick columns by name. filter() picks rows; select() picks columns.
  • mutate() adds new columns calculated from existing ones, with new_name = calculation. The calculation is done for every row at once. Arithmetic with NA gives NA.
  • Sorting a new column with arrange() is a quick way to find outliers. Check them before you trust them.
