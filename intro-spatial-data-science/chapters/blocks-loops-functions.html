5  Blocks, Loops, and Functions

NoteLearning objectives

By the end of this chapter you should be able to:

  1. Explain what a block of code is and how curly braces mark one.
  2. Use if and else to run a block only when a test is TRUE.
  3. Repeat a block with a while loop or a for loop, and avoid an infinite loop.
  4. Decide when you need a loop and when a vectorized function already does the job.
  5. Write a function with one or more arguments, a default value, and a return value.
  6. Explain why a function’s arguments don’t change the variables outside it.

What is the first virtue of a programmer? Ingenuity? Grit? Devotion to R? Larry Wall, who created the Perl programming language, gave a surprising answer: laziness. He meant a particular kind of laziness: refusing to do the same work twice. A lazy programmer writes a piece of code once and reuses it, instead of typing (or copying and pasting) the same steps again and again.

This chapter covers the R tools that let you be productively lazy. Blocks group lines of code together. if statements decide whether a block runs, and loops decide how many times it runs. Functions, which you have been calling since Chapter 2, give a block a name so you can run it again with new inputs.

5.1 Blocks group lines of code

A block is the code between a pair of curly braces, { }. R reads everything from the opening brace to the matching closing brace and treats it as one unit:

All three lines run together, and R prints 10. On their own, braces don’t change much. Their power comes when you attach them to an if, a loop, or a function, which decide whether, or how many times, the block runs. A block either runs completely or is skipped completely.

Two habits make blocks easy to read:

  • Indent the lines inside a block by two spaces. RStudio does this for you when you press Enter after a {. The indentation shows at a glance where a block starts and ends.
  • Check your braces. Every { needs a matching }. A missing closing brace is one of the most common errors in R. When it happens, the Console shows a + prompt, because R is waiting for the rest of the block. Press Esc to start again.

The most common blocks are if statements, while loops, for loops, and functions. We’ll take them in that order.

5.2 if statements run a block only when a test is TRUE

An if statement has two parts: a test in parentheses and a block in braces. R works out the test. If it is TRUE, the block runs. If it is FALSE, R skips the whole block.

if (test) {
  # runs only when test is TRUE
}

5.3 while loops repeat a block while a test is TRUE

A while loop looks like an if statement, but instead of running its block once, it goes back to the test after every run. As long as the test is TRUE, the block runs again:

R checks the test (is 11 less than 100?), runs the block (x becomes 12), checks the test again, and so on. When x reaches 100 the test is FALSE and the loop stops, so x is 100.

WarningWatch out for infinite loops

The block must change something in the test, or the test never becomes FALSE and the loop never ends. If R seems stuck, click the red stop sign at the top of RStudio’s Console, or press Esc.

In practice, R users rarely write while loops. A for loop, or a function that works on a whole vector at once, is almost always simpler.

5.4 for loops run a block once for each item

A for loop doesn’t have a TRUE or FALSE test. Instead, it walks through a vector one item at a time. On each pass, the loop variable takes the next item:

On the first pass county is "Orange", on the second "Durham", and on the third "Wake". After the last item the loop stops on its own, so a for loop can’t run forever. That makes it safer than a while loop.

Use a for loop when you know what you want to repeat over: a set of files, counties, or years. This loop reads each CSV file in a folder and prints how many rows it has:

files <- list.files("data", pattern = "\\.csv$", full.names = TRUE)

for (f in files) {
  d <- read.csv(f)
  print(nrow(d))
}

5.5 Functions name a block so you can reuse it

A function is a block with a name, inputs, and an output. You have already called many functions, such as mean(), round(), and read.csv(). Now that you know what a block is, you can write your own. Every function has the same parts:

name <- function(argument1, argument2) {
  # the body: a block of code
  result <- ...
  result          # the last value is the output
}
  • Name. You create a function the same way you create any object, with <-.
  • Arguments. The inputs, in parentheses after the word function. Inside the body they are placeholders for whatever you pass in.
  • Body. The block between the braces.
  • Return value. The value of the last line in the block is what the function returns. You can also write return(result) to make it explicit.

5.5.1 A preview: the weighted mean center

In Chapter 17 you’ll use a function, meanCenter(), that finds the weighted mean center of a map layer. You don’t need to follow its spatial steps yet, but you can already pick out its parts. Its name is meanCenter, its arguments are layer and weights, its body turns polygons into centroids and takes the weighted mean of their coordinates, and its last line, mean_center, is the return value:

meanCenter <- function(layer, weights) {
  # convert the polygons into points
  points <- st_centroid(layer)
  # weighted mean of the x and y coordinates
  mc_x <- weighted.mean(st_coordinates(points)[, 1], weights)
  mc_y <- weighted.mean(st_coordinates(points)[, 2], weights)
  # create a point with the same CRS as the input layer
  mean_center <- st_sfc(st_point(c(mc_x, mc_y)))
  mean_center <- st_set_crs(mean_center, st_crs(layer))
  mean_center
}

mc_pop <- meanCenter(nc_counties, nc_counties$popE)

addSeven(1) returns 8, and numbers is still 10. Inside the function, numbers means whatever you passed in, here 1. Each time a function runs, R gives it a fresh, private workspace, called its local environment, and throws that workspace away when the function finishes. The numbers in your own workspace, the global environment, is never touched.

  sum(values > cutoff)

5.9 Summary

  • A block is code inside curly braces { } that R runs as one unit. Indent it, and match every { with a }.
  • An if statement runs its block only when its test is TRUE. else gives a second block for FALSE, and else if chains more tests. The test must be one TRUE or FALSE; use ifelse() for a whole vector.
  • A while loop repeats its block while its test is TRUE. Something in the block must move the test toward FALSE, or the loop never ends.
  • A for loop runs its block once for each item in a vector, then stops. Fill a vector made before the loop to keep the results.
  • Many R functions are vectorized, so check for one before you write a loop.
  • A function is a named block: name <- function(arguments) { body }. The last line is the return value. Arguments can have default values.
  • A function’s arguments live in its own local environment, so a function never changes your variables unless you assign its result.
